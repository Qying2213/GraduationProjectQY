# 代码导读与新人上手

这份文档的目标不是重复接口文档，而是回答新人最常问的 4 个问题：

1. 项目从哪里启动
2. 请求会经过哪些层
3. 遇到一个需求时应该先看哪些文件
4. 哪些地方最容易读懵

## 1. 先建立全局地图

项目是一个“Vue 前端 + Go 多服务后端 + PostgreSQL 共享数据库”的招聘平台。

推荐先看这几个入口文件：

- 根目录 [README.md](/Users/qinyang/Desktop/GraduationProjectQY/README.md)
- 快速启动指南 [快速启动指南.md](/Users/qinyang/Desktop/GraduationProjectQY/docs/快速启动指南.md)
- 前端路由入口 [index.ts](/Users/qinyang/Desktop/GraduationProjectQY/frontend/src/router/index.ts)
- JWT 中间件 [jwt.go](/Users/qinyang/Desktop/GraduationProjectQY/backend/common/middleware/jwt.go)
- 当前简历服务入口 [main.go](/Users/qinyang/Desktop/GraduationProjectQY/backend/resume-service/main.go)

如果你只看业务代码、不先看入口，很容易不知道某个接口到底是从哪里进来的。

## 2. 前端代码怎么看

推荐阅读顺序：

1. 看 [index.ts](/Users/qinyang/Desktop/GraduationProjectQY/frontend/src/router/index.ts)
   先弄清楚后台、求职者门户、数据大屏分别挂在哪些路由下面。
2. 看 [user.ts](/Users/qinyang/Desktop/GraduationProjectQY/frontend/src/store/user.ts)
   这里决定了登录态、角色、token 如何保存。
3. 看 `src/api/*.ts`
   这里是页面和后端接口之间的薄封装。
4. 看具体页面 `src/views/...`
   页面负责交互和展示，真正的接口地址通常在 `api` 层。

可以把前端理解成 4 层：

- `router`：页面怎么组织
- `store`：登录态和全局状态怎么保存
- `api`：HTTP 请求怎么发
- `views/components`：页面和组件怎么展示

## 3. 后端代码怎么看

每个业务服务基本都遵循同一个阅读顺序：

1. `main.go`
   看服务启动、数据库连接、路由注册、JWT/角色中间件
2. `handlers/*.go`
   看接口逻辑、参数绑定、数据库查询、响应格式
3. `models/*.go`
   看表结构、状态字段、GORM 标签
4. `common/middleware/*.go`
   看认证、权限、操作日志、跨域

可以把后端理解成 3 层：

- `main.go`：装配层，决定服务暴露什么接口
- `handlers`：接口层，处理 HTTP 请求
- `models`：数据层，描述数据库表结构

## 5. 一个请求通常怎么流转

以“求职者投递职位”为例：

1. 前端页面发起请求
2. 请求经过网关转发
3. 进入 `resume-service` 的 `CreateApplication`
4. 写入 `applications` 表
5. 读取 `jobs` / `talents` 表补充业务信息
6. 写入 `messages` 表，给 HR 发送系统通知

这里有一个很重要的项目特点：

虽然代码按服务拆开了，但当前项目很多服务仍然共享同一个 PostgreSQL 数据库。
所以你会在一个服务里直接访问别的业务表，比如：

- `resume-service` 直接查 `jobs`、`talents`
- `resume-service` 直接写 `messages`

这会让开发更快，但新人第一次看代码时容易困惑：
“为什么消息表不是在 message-service 里写？”

答案是：当前架构是“服务拆代码、数据库仍共享”，不是严格的一库一服务。

## 6. 最容易读混的几个概念

### Application 里的 `Stage` 和 `Status`

- `Stage`：流程走到哪里
- `Status`：当前处理结果是什么

如果后面你发现某些状态值重复，不要惊讶，这就是这个模型目前的历史设计痕迹。

### Resume 里的 `FilePath` 和 `FileURL`

- `FilePath`：服务器磁盘上的真实路径，给后端读文件用
- `FileURL`：前端访问地址，给浏览器下载或预览用

### JWT 里的 `user_id` 和业务里的 `talent_id`

- `user_id`：登录账号 ID
- `talent_id`：人才档案 ID

它们不是同一个字段，所以你会看到某些接口先拿 `user_id`，再去 `talents` 表换出 `talent_id`。

## 7. 新人调试时最推荐的落点

如果你想快速建立直觉，建议先打断点或打印日志看这几条链路：

- 登录：前端登录页 -> `userStore.login` -> JWT 下发
- 查看简历列表：前端页面 -> `/api/v1/resumes` -> `ListResumes`
- 投递职位：前端投递动作 -> `CreateApplication`
- 修改投递状态：后台操作 -> `UpdateApplication` -> 消息通知写入

## 8. 阅读建议

不要一开始就试图把整个仓库逐行读完，更有效的顺序是：

1. 先从入口文件建立地图
2. 再围绕一个完整业务流程跟一遍调用链
3. 最后再回头细看模型字段和边界处理

如果后续还要继续补注释，优先级建议是：

1. `handlers`
2. `main.go`
3. `models`
4. `store/router/api`

因为新人最先卡住的，通常不是算法，而是“不知道请求是怎么从页面走到数据库的”。

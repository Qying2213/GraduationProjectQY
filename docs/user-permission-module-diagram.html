用户登录认证与角色校验流程图

JWT 登录认证 + 简单角色访问控制

受保护接口请求处理流程
1. 用户登录
提交用户名或邮箱、密码
→
2. 后端校验
密码和 active 状态
→
3. 生成 JWT
写入 user_id、username、role
→
4. 前端保存 Token
请求时加入 Authorization
→
5. JWTAuth
校验 Token 是否有效
→
6. RoleAuth
判断角色是否允许访问接口
通过：继续访问职位、人才、面试、消息等业务接口
不通过：返回 401 未登录或 403 无权限

当前代码中的实际控制点

  • 登录成功后生成 JWT，Token 中包含用户 ID、用户名和角色。
  • 前端 Axios 拦截器自动携带 Authorization 请求头。
  • JWTAuth 负责身份认证，RoleAuth 负责简单角色校验。
  • 后台写操作接口主要允许 admin、hr、hr_manager、recruiter 访问。

说明边界

  • 该模块参考 RBAC 思想，但不是完整的动态 RBAC 权限平台。
  • 角色和接口允许范围主要在代码中配置，而不是通过数据库权限表动态维护。
  • 前端路由守卫和按钮权限主要用于展示控制，后端中间件提供接口兜底校验。
  • 求职者相关接口会根据 JWT 中的 user_id 绑定个人简历和投递数据。

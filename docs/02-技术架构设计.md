# 技术架构设计

## 一、总体架构

系统采用“前后端分离 + API 网关 + 微服务 + AI 能力集成”的架构模式。

整体链路如下：

```text
Vue3 前端（管理后台 / 求职者门户 / 数据大屏）
        ↓
API Gateway
        ↓
业务微服务（用户 / 职位 / 面试 / 简历 / 消息 / 人才 / 推荐 / 日志）
        ↓
PostgreSQL / Redis / Elasticsearch / Coze / Embedding API
```

- 投递

### 3. Elasticsearch

用于：

- 操作日志存储
- 全文检索
- 审计追踪

## 五、AI 评估架构

当前 AI 评估主链路已经演进为：

```text
简历文件
  -> OCR / 文本提取
  -> Embedding 向量化
  -> RAG 检索增强
  -> Coze 工作流评估
  -> 结构化结果入库
```

其中：

- `resume-service` 负责上传、OCR、Embedding、RAG 和 Coze 调用
- Coze 工作流当前支持同时接收：
  - `resume_file`
  - `resume_text`
  - `jd_text`
  - `name`
- `resume_text` 优先用于结构化提取，`resume_file` 作为兜底输入

## 六、高并发设计

### 1. 微服务拆分

系统通过服务拆分降低耦合，使不同业务模块可以独立扩展与部署。

### 2. Goroutine 并发模型

Go 原生协程用于提升高并发场景下的吞吐能力，特别适合：

- 接口并发处理
- 日志写入
- 部分异步任务

### 3. 多级缓存与读写分离思路

```text
请求
 -> 本地缓存 / 业务内存缓存
 -> Redis
 -> PostgreSQL
```

### 4. AI 链路性能策略

- OCR 先尝试直接文本提取，降低纯图片 OCR 成本
- Embedding 文本长度截断，控制单次请求成本
- RAG 查询 `top_k=3`，避免无效上下文膨胀
- AI 评估超时控制在分钟级，防止长时间阻塞

## 四、测试方法

本次测试采用“自动化脚本 + 前端构建验证 + 性能压测 + 人工补充复核”四种方式结合：

1. 自动化接口测试  
   使用 `ztest` 下的全链路测试脚本与毕业设计专项验收脚本，验证服务可用性、接口正确性、业务闭环和权限控制。

2. 前端测试  
   验证前端单元测试、前端 API 集成测试以及生产构建是否成功。

3. 性能压测  
   通过 `scripts/benchmark.sh` 对关键读接口进行微服务直连压测，记录 QPS、平均延迟与 P99。

4. 人工补充复核  
   对 AI 简历评估链路进行单样本补充验证，确认 OCR 文本提取结果、结构化字段提取结果和最终评分结果是否与预期一致。

### 4. 当前观察到的边界问题

虽然链路整体可用，但本轮人工复核也发现两个仍可继续优化的点：

1. 姓名字段有时仍使用文件名而非纯姓名  
   原因是当前仍保留 `name` 入参使用文件名的策略。

2. 技术能力得分偏保守  
   当 `skill` 抽取信息不足时，技术评分节点可能打出较低分值。该问题属于提示词与评分策略优化空间，不影响“链路可用”这一毕业设计验收结论。

因此，从毕业设计视角看，AI 评估链路已达到“可演示、可复现、可解释”的交付标准；从工程优化视角看，后续仍有进一步提升空间。

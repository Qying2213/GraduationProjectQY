# AI 集成方案

## 一、概述

本项目的 AI 能力主要集中在两个方向：

1. 简历智能评估  
   由 `resume-service` 负责发起，结合 OCR、Embedding、RAG 与 Coze 工作流完成结构化解析和评分。

2. 推荐归因与解释  
   由 `recommendation-service` 负责部分推荐解释能力，输出匹配理由与细节说明。

## 二、当前 AI 技术路线

### 1. 简历评估链路

```text
简历文件
  -> OCR / 文本提取
  -> Embedding 向量化
  -> RAG 检索增强
  -> Coze 工作流
  -> 结构化评估结果
```

### 2. 推荐解释链路

```text
职位画像 / 人才画像
  -> 匹配算法
  -> 推荐结果
  -> 归因说明 / 匹配细节
```

## 三、环境变量配置

当前项目中与 AI 相关的主要变量如下：

```bash
COZE_BASE_URL=https://api.coze.cn
COZE_TOKEN=
COZE_WORKFLOW_ID=

COZE_API_TOKEN=
COZE_ATTRIBUTION_WORKFLOW_ID=

VOLC_ENDPOINT=https://ark.cn-beijing.volces.com/api/v3/embeddings/multimodal
ARK_API_KEY=
VOLC_MODEL_ID=doubao-embedding-vision-251215
```

说明：

- `COZE_TOKEN + COZE_WORKFLOW_ID`  
  当前主要用于 `resume-service` 的 AI 评估工作流。

- `COZE_API_TOKEN + COZE_ATTRIBUTION_WORKFLOW_ID`  
  兼容用于推荐归因等其他 Coze 工作流场景。

- `ARK_API_KEY + VOLC_ENDPOINT + VOLC_MODEL_ID`  
  用于 Embedding 向量化。

## 四、Coze 工作流输入设计

### 1. 当前简历评估工作流输入

当前工作流已支持以下输入：

| 参数名 | 类型 | 说明 |
|---|---|---|
| `name` | string | 候选人名称或文件名 |
| `jd_text` | string | 职位描述 |
| `resume_file` | file | 原始简历文件 |
| `resume_text` | string | 后端 OCR / 文本提取结果 |

### 2. 当前策略

工作流中已采用“双输入”策略：

- 优先使用后端传入的 `resume_text`
- `resume_file` 仍保留作为兜底输入

这样做的好处是：

1. 避免完全依赖 Coze 自身文件解析稳定性
2. 让本地 OCR、Embedding、RAG 和 Coze 主评估尽量使用同一份文本
3. 降低“文件能上传但字段全空”的异常概率

## 五、resume-service 中的 AI 调用方式

### 1. OCR

当前 `resume-service` 会先对 PDF / DOC / DOCX 做文本提取：

- 优先尝试文本型 PDF 直接提取
- 对噪声文本做归一化和水印清洗
- 必要时回退到图片 OCR

### 2. Embedding

当 OCR 得到有效文本时，会调用火山引擎接口生成向量。

当前实现特征：

- 文本会做长度控制
- 使用 HTTP API 同步返回向量
- 速度通常快于 LLM 生成阶段

### 3. RAG

向量化完成后，系统会向 `recommendation-service` 查询相似人才上下文，用于增强 JD 评估信息。

### 4. Coze 评估

当前 `resume-service` 发送给 Coze 的参数已经包含：

- `name`
- `jd_text`
- `resume_text`
- `resume_file`

其中 `resume_text` 是近期新增接入的关键参数，目的是让 Coze 主评估优先利用本地 OCR 文本。

## 六、典型提示词策略

### 1. 简历解析节点

当前工作流中，简历解析提示词核心思想是：

- 如果 `resume_text_backend` 非空，则优先使用它
- 只有在后端 OCR 文本为空时，才使用 `resume_image` / `read.data`
- 不拼接两份文本，避免噪声叠加

### 2. 技术评分节点

当前建议的评分原则是：

- “信息不足”不等于“技术不匹配”
- 候选人存在明确核心技术关键词时，不应直接打 0 分
- 技术评分应结合 `skill`、`work_exp` 和 `jd_text` 综合判断

## 七、当前 AI 能力的已验证结果

根据 2026-04-01 的实际验证结果：

- OCR 文本提取长度可达数千字符
- Coze 已不再返回“全 0 / 全空”的评估结果
- 学历、学校、工作经验等核心字段可恢复提取
- JD 匹配度、维度评分、录用建议可正常输出

## 八、当前局限与优化方向

虽然 AI 链路已达到交付要求，但仍存在可优化空间：

1. 姓名标准化仍可能受文件名影响
2. 技术能力评分在信息不足时仍偏保守
3. AI 处理流程页的“实时步骤展示”目前还不是真正逐步进度
4. 如果从严格学术实验角度出发，仍可进一步补充标准化样本集评估

## 九、适合论文中的写法建议

在毕业论文中，本章可以这样表述：

- AI 并不是单点调用，而是嵌入业务链路的工程化能力
- 采用“传统工程能力 + 大模型能力”混合方案，而不是完全依赖单一模型
- 通过 OCR、Embedding、RAG、Coze 工作流的串联，提高了简历解析与评估结果的稳定性和可解释性
